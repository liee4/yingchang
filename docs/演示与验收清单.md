# 映场演示与验收清单

这是程序操作与验收说明，不是课程结题报告。

## 启动与数据

Windows 双击根目录「启动映场.cmd」。需要 Node.js 18+，以及支持 C++17 的 g++（在 PATH 中）或通过 CXX 指定的编译器。无需 npm install。第一次会编译核心，随后按源码摘要复用。复制到其他机器后重新编译，不依赖本机绝对路径。

默认地址：http://127.0.0.1:4173/ 。重复启动会核对健康接口和数据目录，确认相同后复用；端口被其他服务占用时会说明原因。可用 `node web/scripts/serve.mjs --port 4180` 换端口。同一数据目录只允许一个核心进程写入。

数据在根目录 data 中：documentaries.txt、reviews.txt、users.txt。更换电脑需要复制整个项目及 data；仅复制网页静态包无法运行 C++ 业务。服务重启后重新登录，账号和评价保留。

初始管理员：admin / admin123。观众自行注册；新管理员用已有管理员在「我的账户与评价」生成的单次邀请码注册。

后台「备份全部数据」由 C++ 顺序复制三份文件，生成 data/backups/snapshot-时间戳/ 和 manifest.json。恢复时先关闭网页服务，保留当前三份文件副本，再把同一次备份的三份文本一起复制回 data；重新启动。不要混用不同时间的文件或在运行时覆盖。备份含账号摘要，应随项目妥善保管。

## 推荐演示顺序（约 8–10 分钟）

1. 登录：展示密码遮罩；用错误密码登录三次，看到「本次登录已结束」和重新登录入口；再正确登录。
2. 浏览：默认显示全部影片，可按题材筛选或点「全部影片」恢复列表。展示居中轮播、侧翼渐隐、左右按钮。打开详情，展示简介、分集选读/目录、来源、封面说明。
3. 搜索：试「顺德」「BBC 自然」「Forest」或已有片号；多词须同时匹配。空结果可清空搜索和筛选。打开详情后返回，保留筛选、关键词和页面位置。
4. 评价：选一部影片，内容 5、画面 4、讲解 3，综合为 4.25。再将讲解改为 5，综合为 4.75，人数不因本人复评增加；重新打开能填入上次评价。已有其他评价时，影片均分还要与它们平均。
5. 榜单：查看前三推荐和前十表格，切换综合、内容、画面、讲解。综合分按 (2×内容+画面+讲解)÷4；同分按人数降序、片号升序，未评分片目不入榜。明确演示评价参与计算，得分不是外部平台评分。
6. 管理：新增一部测试影片，填写简介、看点、分集、来源，选择本地封面。改名后查看原评价仍属于相同片号。添加重复片号会报错；不存在的片号不能修改/评价。
7. 统计：输入「3 4」查看 [1,3)、[3,4)、[4,5]。展示总图、数量、百分比与逐片表格；边界归后一段。输入重复或不递增分界点应报错。
8. 持久化：先备份，退出并重新启动。确认刚刚的片目、评价和账号仍存在。测试删除应使用独立副本，确认片目和关联评价一起删除。

## 自动化验收

- 根目录 `npm test`：32 项 HTTP/C++ 集成检查，覆盖三次失败、权限、账号持久化、复评、非法评分保护、排序并列、前十、未评分排除、字段完整修改/清空、删除联动、重启、备份、锁、迁移、失败恢复，以及只修改 C++ 权重时网页返回结果同步变化。
- `npm run test:cpp`：C++ 业务类和终端调试菜单回归。
- `npm --prefix web run build` 和 `npm --prefix web run test:sites`：静态资源打包及 4 项包装检查；不代表静态托管环境可以执行 C++。

测试使用临时数据目录。实际数据保留 28 部影片（18 真实 + 10 旧版）、41 条评价，其中 39 条标为演示；这是本轮核验时的数量，后续操作会改变。

本轮还验证了无 data、无 cpp/build 的全新复制目录，首次编译后由 C++ 初始化 18 部真实影片、24 条演示评价。未实际在另一台物理电脑上运行。

影片简介是基于来源资料整理的观影介绍。部分分集目录是选读，部分封面是主题插画，页面已标注。9 部缺失主创署名本轮补充；BBC 系列已将系列制片人和执行制片人归入主创，尚未逐一核实的分集导演明确标为待核实。神奇的嫦娥五号区分原系列导演与电视整合版署名。具体来源与核验说明见 web/CONTENT_SOURCES.md 和 resources/credits-enrichment.json。
