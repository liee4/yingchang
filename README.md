# 映场：网页界面 + C++ 核心

纪录片放映周评价与推荐系统。正常操作只有一个网页入口，Node.js 提供网页、登录会话和通信桥接，C++ 完成全部业务并读写唯一的一套片目、评价文件。终端菜单仅用于调试，共享同一数据目录。

## 启动

收到协作完整版 ZIP 时，先完整解压并阅读「协作者请先读.md」。该包附有 Windows x64 Node.js 与 C++ 程序，可直接双击「启动映场.cmd」运行。修改 C++ 后需安装编译器并运行「重新编译核心.cmd」；便携入口会校验源码与二进制是否一致。以下依赖说明适用于从源码编译运行。

需要 Node.js 18+ 和支持 C++17 的 GCC（g++）。无需 npm install。首次启动会自动编译 C++，之后源码没有变化则复用编译结果；启动后不需要联网。

Windows 双击本目录的 **启动映场.cmd**，程序会启动本地服务并打开浏览器。也可以在项目根目录运行 `npm start`。服务地址为 [http://127.0.0.1:4173/](http://127.0.0.1:4173/)。关闭服务窗口前先完成当前操作。

管理员初始账号：`admin` / `admin123`。观众与管理员统一使用登录页。注册时填写账号、昵称和密码，成功后返回登录页重新输入账号和密码。管理员登录后在「我的账户与评价」生成一次性邀请码，新管理员选择管理员身份注册时填写该码。邀请码 24 小时有效，使用一次后失效。

评价自动绑定当前账号的固定观众编号，同一账号复评更新原记录。观众可删除自己的短评，管理员可在「全部评价」删除任意短评，评分继续参与统计。观众端按昵称展示评价，后台按编号展示。「我的账户与评价」集中显示本人评价。服务重启后需重新登录，账号和评价仍会保留。密码以随机盐和 scrypt 派生摘要保存。

观众可在两页气泡界面选择影片题材与画面风格。从登录入口进入偏好设置后，匹配片目出现在首页「为你展映」，焦点影片封面同步成为虚化背景。影片详情支持收藏，顶部「收藏」和「历史」可打开影片及移除记录，历史还可一键清空。偏好、收藏和浏览历史随观众账号保存在服务端，仅本人可通过网页访问。旧版浏览器共用记录没有账号归属，网页不会自动导入。

首页展映支持点击左右侧卡片或箭头切换、方向键切换与触屏滑动；当前影片始终居中，侧翼渐隐。搜索支持片名、原名、导演、主创、类别、地区、简介和精确片号；多个关键词用空格分隔并同时匹配。输入时显示建议，方向键选择、回车打开，Esc 关闭，按 `/` 聚焦搜索。

片库默认展示全部影片，可按题材筛选，演示片目会标注。管理后台支持完整资料编辑（含年份、原名、地区、语言、时长、推荐语、看点、分集、来源及本地封面选择），并可备份片目、评价和账号。详情页三项均分、推荐榜及分布图数量/百分比都来自 C++。连续三次登录失败会结束本次登录并返回入口。

实际演示步骤、备份恢复和课程验收用例见 [演示与验收清单](docs/演示与验收清单.md)。

## 数据与迁移

唯一的运行数据保存在项目根目录：

- `data/documentaries.txt`：每行一条 UTF-8 JSON 片目记录，含课程必需字段及年份、海报编号、画面风格、看点、分集和来源。
- `data/reviews.txt`：每行一条 UTF-8 JSON 评价记录。
- `data/users.txt`：C++ 保存的 UTF-8 JSON 账号资料、观众偏好、收藏、浏览历史与邀请码摘要，使用临时文件原子替换。密码和邀请码均以摘要保存。

文本中的换行、引号与反斜线由 JSON 转义保存。C++ 也能读取旧终端版的引号分隔文本；下一次保存会转换成新格式。分数、人数和榜单不存为独立数据，每次由 C++ 计算。

首次运行会由 C++ 检查旧 `web/data/catalog.json` 和 `cpp` 下的旧文本文件，先校验、备份，再导入统一目录。备份与迁移清单位于 `data/backups/migration-*/`；迁移成功后旧活动文件归档至备份目录，不再读写。保留片号及用户修改；如果网页与终端的相同编号对应不同影片或评价，停止迁移并保留原文件，不擅自重新编号。

没有旧数据时，从 `resources/catalog-seed.json` 初始化 18 部真实纪录片与明确标记的演示评价。该文件是只读初始化资料，不是另一套运行数据库。已有数据时不会重复灌入，管理员删除的片目不会因重启重新出现。

数据目录有独占锁；不能同时运行两个服务或一边运行网页一边运行调试终端。双文件写入使用临时文件和事务标记，保存中断时在下次启动完成恢复。数据文件损坏、缺失其中之一或核心退出时会明确报错，不自动改用 JavaScript 或样例数据。

## 代码结构

| 部分 | 位置 | 职责 |
|---|---|---|
| 网页 | `web/src/` | 展示、表单与结果格式化 |
| HTTP 与登录 | `web/scripts/catalog-api.mjs` | 会话、权限、请求转发 |
| C++ 通信桥 | `web/scripts/core-client.mjs` | 常驻子进程、请求编号、超时和退出处理 |
| C++ 业务入口 | `cpp/core_service.cpp` | 查询、维护、复评、计算结果和统计 |
| C++ 业务类 | `cpp/documentary_catalog.*`、`cpp/reviews.*` | 片目与评价结构、复评、评分、排名 |
| 数据格式与校验 | `cpp/record_codec.*` | 基础及扩展字段校验、JSON 编解码 |
| 统一存储 | `cpp/data_store.*` | 目录锁、迁移备份、双文件提交与恢复 |
| 账号存储 | `cpp/accounts.h` | 账号校验、固定观众编号、管理员邀请与原子保存 |
| 初始资料 | `resources/catalog-seed.json` | 真实片目、来源与旧数据兼容基线 |

Node.js 启动 C++ 的 `--stdio` 模式，一行请求对应一行 JSON 结果；标准输出不混入菜单，日志写入标准错误。网页接口地址沿用原版，同时增加查询、分布与健康状态接口。可访问 `/api/health` 核对 C++ 进程和统一目录。

综合分公式、四类榜单和分数段统计都在 C++ 中。`cpp/reviews.cpp` 的 `contentScoreWeight` 默认是选题要求的 2；修改后重新启动会自动重编译，网页公式和结果也从 C++ 更新。

## 验证与调试

- 在根目录执行 `npm test`：HTTP→Node→C++→文本文件的集成测试，含并发、权限、迁移、重启、故障恢复及 C++ 规则改动验证。
- 执行 `npm run test:cpp`：C++ 类与终端菜单回归测试。
- 执行 `npm run debug:cpp`：调试菜单。需要先停止网页服务，读取的仍是根目录 `data`。
- 在 `web` 中执行 `npm run build`、`npm run test:sites`：验证静态资源打包。该静态包不含可托管 C++ 的业务服务，完整演示使用本地入口。

测试只使用系统临时目录，不写入实际演示数据。C++ JSON 库是已随项目提供的 nlohmann/json v3.12.0，来源与 MIT 许可见 `cpp/third_party/`。可用 `CXX` 指定编译器，或用 `YINGCHANG_CORE_EXECUTABLE` 指定已编译的核心程序；更换机器后正常启动会重新编译。

真实影片资料与图片出处见 [内容来源](web/CONTENT_SOURCES.md)，通信与文件约定见 [整合说明](INTEGRATION.md)。
